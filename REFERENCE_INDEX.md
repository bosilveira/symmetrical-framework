# Symmetrical Framework — Reference Index and Research Protocol

**Repository entry point · 21 November 2026.** This document is meant to be read first by a new reader or assistant. It is a navigation and evidence protocol, **not** an assertion that all existing files are verified. Begin with the exact repository branch and source revision. This root index is intentionally independent of chat memory.

## 1. What is authoritative today?

There are **two different, actively relevant organizations**, and they are not yet reconciled into one published reference.

| Branch | Actual contents and role | Verification caution |
|---|---|---|
| [main](https://github.com/bosilveira/symmetrical-framework/blob/main/README.md) (default) | A newly started, numbered, four-layer foundational series, with explicit document IDs and draft metadata; plus a substantial numbered [draft investigation archive](https://github.com/bosilveira/symmetrical-framework/blob/main/draft/README.md) | The three foundational chapters are individually marked **draft**. Review the proof and its hypotheses, not just the status label |
| [feat/part-i-rigorous-revision](https://github.com/bosilveira/symmetrical-framework/tree/feat/part-i-rigorous-revision) | The eight-part encyclopedia-style collection; extensively revised Chapters 1–4 of Part I, with checks and correction ledgers | Later Parts II–VIII and the 'identities', 'theorems', and conversational archive files have mixed maturity; **do not assume they are canonical or fully checked** |

**Source priority is claim-specific, not simply branch-specific.** For an assertion, open the exact numbered theorem and its proof on the branch being cited, inspect its review notes, and compare competing formulas explicitly if they conflict. Prefer the document with a complete proof, declared hypotheses, and verifiable tests over an unsourced summary. An archive or a previous chat is evidence of investigation, not an authority. If two maintained documents disagree, record the discrepancy instead of selecting one silently.

For a reproducible citation provide **branch + document path + document/claim ID or equation anchor + commit SHA**. Branch links show the current version; commit links reproduce a particular historical statement.

## 4. Minimal notation dictionary

Default real domain, unless a source explicitly changes it: $`x>0`$, $`c>0`$, $`r>0`$, and $`\mu>0`$ for the coupled normalization. The canonical coordinate is **$`u=\log(x/c)`$**, never $`u=x/c`$; write $`\xi=x/c`$ for the dimensionless spatial ratio and $`\theta=ru`$ for the hyperbolic argument. The scale $`c`$ remains explicit even when the autonomous equation loses it.

```math
f(x;r,c)=\frac{c^r x^{r-1}}{c^{2r}+x^{2r}},\qquad S(u)=2xf(x;r,c)=\mathrm{sech}(ru),\qquad W(u)=\tanh(ru).
```

```math
f_\mu=\frac{f}{\sqrt\mu},\qquad y(u)=2xf_\mu(x),\qquad \varepsilon=y_u^2-r^2y^2+\mu r^2y^4.
```

Write $`D=x\partial_x=\partial_u`$ **with** $`c`$ fixed. An $`x`$-derivative is not a $`u`$-derivative. When a general Master solution is considered, do **not** silently replace it by the selected hyperbolic-secant solution or assume zero energy.

## 5. Evidence, statuses, and logical arrows

Status labels vary historically: the main foundational series uses **[T]** proof, **[V]** computational check, **[K]** known literature, **[I]** interpretation and **[C]** conjecture; the revised Part I has used **[E]** exact, **[K]** classical, **[C]** selected construction and **[O]** open. In particular **[C] means two different things**. Until the registry migration is complete, always read each file's own legend.

For future entries, maintain separate fields:

| Field | Suggested values | Meaning |
|---|---|---|
| **statement_status** | proved / computationally-checked / literature / provisional / refuted / superseded | Whether the exact statement is established |
| **statement_kind** | definition / identity / theorem / construction / conditional-correspondence / conjecture / interpretation / model | What kind of mathematical object/claim it is |
| **hypotheses** | explicit domain, positivity, regularity, energy, boundary data | Necessary conditions; cannot be omitted |
| **evidence** | proof location, calculation, code test, counterexample, literature citation | What justifies the status |
| **dependencies** | stable IDs and exact equation references | Which other assertions are used |
| **validity_scope** | global / local / branch-dependent / normalization-dependent | Range of applicability |

Do not infer **converse**, **equivalence**, **uniqueness**, **physical realization**, or **novelty** from a single identity. Write arrows as implications unless the inverse map is proved with matching domains. For new claims, allocate an unused stable ID, cite its source and tests, then update the subject index. Do not silently reuse existing F-, D-, H- or SF- identifiers.

## 6. DLMF-inspired editorial plan (staged, no destructive moves)

Adopt DLMF's **navigability**, not its numeric chapter scheme. A future canonical reference entry should include (a) a stable ID, (b) precise theorem statement and notation, (c) explicit hypotheses and branch choices, (d) proof, (e) equation anchors, (f) related formulas and converse limitations, (g) references, (h) verification, and (i) errata/revision record. DLMF itself separates chapters, sections, equation-level permalinks, notation and errata. See [DLMF §13.13](https://dlmf.nist.gov/13.13) and its [home/index](https://dlmf.nist.gov/).

**Phase A — completed in this reference-index commit:** root entry point, agent handoff, branch provenance map, canonical notation, status translation and correction of the default README uniqueness claim. Existing research files stay at their current paths.

**Phase B — next:** inventory all numbered and archived files into a machine-readable crosswalk (branch, path, stable ID, topic, dependencies, statement status, supersession link); detect duplicates, broken links and contradicting formulas, *without modifying theorem text*.

**Phase C — after item-by-item review:** establish a single canonical reference tree with explicit chapter/section IDs and numbered equation anchors. Keep compatibility links or redirect stubs at old paths and retain original Git history. Promote proved content from archives; label unproved hypotheses separately. Distinguish formula catalog from mathematical developments and applications.

**Phase D — ongoing:** automated Markdown, internal-link, equation-ID and symbolic/numerical checks; errata and citation logs; dedicated notation and subject indexes; periodic audits of cross-branch discrepancies.

Avoid a simultaneous massive directory rename: it would destroy reference stability and increase the chance of conflating already-corrected theorems with legacy claims.

## 7. Procedure for future conversations and assistants

1. **Read `AGENTS.md` and this index first.** Then read the main foundational chapter or feature-branch numbered section relevant to the question, including its local notes/corrections. If using GitHub tools, inspect the current branch head before proposing edits.
2. **Recover context by files, not memory assumptions.** Search by concept, variables, stable IDs and formulas; include relevant archival material only as research evidence.
3. **Record the mathematical state.** Identify what is already proved, what is only tested, what is contradicted, and the precise next open task. Explicitly distinguish a classical known result from a new conjecture or novel result.
4. **Retain notation and proof steps.** Keep $`r,c,\mu`$ explicit; use $`u=\log(x/c)`$; verify all transformations, Jacobians, integration constants and energy levels.
5. **For repository changes:** work on the specified branch, preserve historical sources unless removal is requested, run the appropriate test/checker, inspect the final diff, and commit with explicit scope. Do not silently merge feature research into the default branch.
6. **For citations:** give the path/branch/commit and, wherever available, stable equation or proposition ID. Say when a document could not be fetched; a prior chat summary does not replace reading the exact source.

**Accessibility limitation:** this index does **not** automatically inject repository content into every ChatGPT conversation. A new chat must have repository access through a connected tool or the relevant source must be provided. Sharing this index URL or explicitly asking the assistant to open the repository is the reliable handoff.
